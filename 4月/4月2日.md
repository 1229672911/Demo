**中间件与拦截器**

- 中间件是强耦合的，可以参与函数中间的逻辑，而拦截器只起到装饰作用拦截器并无强耦合，可以解耦。

```tex
中间件判定条件：
if (可以中止流程 && 能修改原始输入输出) {
    return "这是中间件";
} else {
    return "这是拦截器";
}

```

中间件可以终止流程和修改原始输出，而典型拦截器一般不能终止流程，而对于输入输出都是只读。

## 登录日志部分

在登录查找用户之后添加一个功能来获取用户登录的信息自动生成日志，同时日志获得的一部分信息也来自于$HTTP$包体



**使用中间件的方式**

```go
// 1. 定义日志中间件
func LoginLogger(db *gorm.DB) gin.HandlerFunc {
    // 返回Gin标准的处理函数
    return func(c *gin.Context) {
        // 先执行后续中间件和业务逻辑
        c.Next()

        // ---------- 以下是日志记录逻辑 ----------
        // 获取HTTP状态码
        statusCode := c.Writer.Status()
        
        // 从上下文中获取登录名
        loginName, exists := c.Get("loginName")
        if !exists {
            loginName = "unknown"
        }

        // 构造日志对象
        log := model.LoginLogDetailDTO{
            OpType:        "用户登录",
            ModuleName:    "认证模块",
            OpStatus:     strconv.Itoa(statusCode),
            RequestMethod: c.Request.Method,
            UserName:      loginName.(sring),
            LoginStatus:   getLoginStatus(statusCode),
            IpAddress:     c.ClientIP(),
            LoginTime:     time.Now(),
        }

        // 异步写入数据库
        go db.Create(&log)
    }
}

// 2. 在登录函数中设置上下文
func login(c *gin.Context, db *gorm.DB) {
    // ...原有登录逻辑...
    
    // 登录成功后保存用户名到上下文
    c.Set("loginName", dbUser.LoginName)
}

// 3. 路由注册时插入中间件
router.POST("/login", LoginLogger(db), login)

```

**执行流程**

```tex
请求进入 → Logger中间件前半部 → login函数 → Logger中间件后半部
           (记录开始时间)     (业务处理)    (记录结果)
```



**使用装饰器的模式**

```go
// 1. 定义装饰器函数
func WithLoginLog(db *gorm.DB, handler gin.HandlerFunc) gin.HandlerFunc {
    // 返回新的处理函数
    return func(c *gin.Context) {
        // 记录开始时间
        start := time.Now()
        
        // ---------- 核心差异点 ----------
        // 直接执行被装饰的函数
        handler(c)
        // ----------------------------
        
        // 获取状态码
        status := c.Writer.Status()
        
        // 获取请求数据
        requestData := getRequestData(c)
        
        // 构造日志对象
        log := model.LoginLogDetailDTO{
            OpType:        "用户登录",
            RequestData:   requestData,
            LoginStatus:   getLoginStatus(status),
            IpAddress:    c.ClientIP(),
            LoginTime:    start,
        }

        // 写入数据库
        db.Create(&log)
    }
}

// 2. 原始登录函数保持不变
func login(c *gin.Context, db *gorm.DB) {
    // ...原有逻辑...
}

// 3. 路由注册时使用装饰器
router.POST("/login", WithLoginLog(db, func(c *gin.Context) {
    login(c, db) // 闭包传递db参数
}))

```

**执行流程**

```tex
请求进入 → WithLoginLog装饰器 → login函数 → 装饰器剩余逻辑
           (前置处理)       (业务处理)   (后置处理)
```



- $gin.HadnlerFunc():$
  -  一般用来处理$HTTP$请求，是一个接收$*gin.Context$参数且没有返回值的函数类型。
  - 中间件和路由处理函数的统一格式，可以像乐高一样组合。

- $c.Next():$ 
  - 与直接执行被装饰的函数相比，$c.Next()$的控制流不是线性执行，而是洋葱模型
  - 可被$Abort()$打断
  - 适用于需要前后置处理复杂的逻辑。

- 在函数中设置上下文，登录后保存用户名到上下文
  - 上下文：可以理解为程序执行的背景环境，包含了在特定时刻程序所需的所有信息。
  - 上下文有以下作用：
    - **状态管理：** 上下文有助于跟踪和管理程序中的状态变化。在多线程环境中，每个线程都有自己的上下文，以避免数据交叉干扰。
    - **函数调用：** 当一个函数被调用时，程序的上下文会切换到这个函数的上下文。函数的执行将在新的上下文中进行，而在函数执行完毕后，程序将返回到原来的上下文。
    - **内存管理：** 上下文有助于管理内存分配和释放。在$C$语言中，当你使用 $malloc$ 分配内存时，上下文记录了这个内存块的信息，以便在不需要时进行释放，防止内存泄漏。
    - **异常处理：** 在程序运行时，如果出现了异常情况，上下文将切换到异常处理的状态，以确保程序可以适当地应对异常。
  - $Set() :$  以键（$string$）值对形式存储，键是快递单号，值可以存任意类型。
  - $Get():$ 返回两个值（$value，exists$），必须做**类型断言**才能使用具体类型。

```go
// 1. 带检查的取用
if val, exists := c.Get("salt"); exists {
    if num, ok := val.(int); ok { // 双重保险
        fmt.Println(num)
    }
}

// 2. 使用结构体包装
type Seasoning struct {
    Salt int
    Sugar float64
}
c.Set("seasoning", &Seasoning{Salt: 5})
```

- 首先取用这个值，存在$val$中，如果存在则判断这个值是否是$int$类型的，如果是则进行之后的一步。

- 在$Set$的时候，使用结构体包装起来要用的值，并对其中的值进行初始化。

- 这里的上下文理解为使用$Set$设置一个口令表示这块变量先存到这，然后使用$Get$的时候就表示要用这个口令来调取这个变量了。

- $Set$的口令完全自由。
