## 过滤器

可以用来筛选、处理数据的组件，他会规则的把想要和不想要的数据分开。

```go
原始数据 → [过滤器] → 合格数据
               ↓
           被过滤的数据
```

过滤器就是一堆条件判定，或者可以创建几个方法，针对每个方法的返回结果进行判定，如果返回False则终止请求，否则继续执行下一个过滤器。

```go
func DataFilter(rawData []byte) (cleanData []byte, err error) {
    // 1. 尺寸过滤
    if len(rawData) > MaxSize {
        return nil, errors.New("数据过大")
    }
    
    // 2. 内容净化
    cleanData = sanitize(rawData)
    
    // 3. 类型校验
    if !json.Valid(cleanData) {
        return nil, errors.New("非法JSON")
    }
    
    return cleanData, nil
}

```



## 拦截器

在$Golang$中，拦截器是一种非常常见的设计模式，它可以用来在函数执行之前或之后拦截并修改其行为。是面向切片编程。

通过在拦截器中添加日志记录、性能监控、错误处理和权限验证等逻辑，可以简化代码、提高模块化和解耦程度，以及增强代码的可维护性。

```go
请求 → [前置处理] → 核心逻辑 → [后置处理] → 响应
            ↓
        [错误处理]
```

日志记录是拦截器最常见的用途之一。通过在函数执行前后插入日志输出的逻辑，我们可以方便地记录函数的调用情况，帮助我们监控程序的运行状态。

比如下边的一个$Go$语言拦截器的示例

```go
package main
 
import (
    "fmt"
    "time"
)
 
func LoggerInterceptor(fn func()) {  //  包装函数
    start := time.Now()//获取当前时间，精确到纳秒。在此记录开始时间
    fmt.Printf("Function started at: %s\n", start)//输出开始时间
 
    fn()  //  执行原函数
 
    end := time.Now()//记录结束时间
    //之后打印结束信息
    fmt.Printf("Function ended at: %s\n", end)//打印结束时间
    fmt.Printf("Execution time: %s\n", end.Sub(start))//计算时间差并输出
}
 
func main() {
    LoggerInterceptor(func() {  //  传入匿名函数
        fmt.Println("Hello, World!")
    })
}

```

最主要的是要传入一个函数作为参数。

$LoggerInterceptor$函数接受一个函数作为参数，并在函数执行前后输出日志信息。在$main$函数中，通过传入一个匿名函数来调用$LoggerInterceptor$函数，从而实现了日志记录的功能。



**？？如果要给这个函数传入的参数是一个需要参数的函数呢？？**

使用函数包装（闭包）

```go
// 泛型拦截器函数
func LoggerInterceptor1[T any](fn func(T)) func(T) {
    return func(arg T) {
        start := time.Now()
        fmt.Printf("参数: %v | 开始: %v\n", arg, start)
        
        fn(arg)  // 执行原函数
        
        fmt.Printf("耗时: %v\n", time.Since(start))
    }
}

// 使用示例：
wrapped := LoggerInterceptor1(func(name string) {
    fmt.Printf("Hello, %s!\n", name)
})//在此传入一个匿名函数作为参数
wrapped("小喵")


//如果要扩展到多参数
func LoggerInterceptor2[T, U any](fn func(T, U)) func(T, U) {
    return func(arg1 T, arg2 U) {
        start := time.Now()
        fmt.Printf("参数1: %v | 参数2: %v\n", arg1, arg2)
        
        fn(arg1, arg2)
        
        fmt.Printf("耗时: %v\n", time.Since(start))
    }
}

//如果要指定具体类型
// 只处理string类型的特化版本
func LoggerForString(fn func(string)) func(string) {
    return func(arg string) {
        // 实现略...
    }
}

```

- $[T\ \ any]：$泛型类型声明，表示可接受任何类型；声明一个**类型参数**，$T$是类型变量名，$any$是约束（表示任何类型）

- 在一开始定义的时候输入参数$fn\ \ func(T)$是一个接受$T$类型参数的函数。同时返回一个同类型的函数$func(T)$

- 整体就是要定义一个能包装任何单参数函数的拦截器。

- 如果要指定参数类型的话，就像指定$string$类型的传参和返回参数的类型

  - 这样写就**失去了泛型的灵活性**，只能处理$string$类型

  - 泛型的优势就在于**避免重复写逻辑相同的代码**

----------

**如果想让拦截器也能处理函数的返回值，该怎么做？**



```go
func LoggerInterceptorWithReturn[T any, R any](fn func(T) R) func(T) R {
    // 泛型声明：输入类型T，返回类型R
    return func(arg T) R {
        // 返回的增强函数
        start := time.Now()
        defer fmt.Printf("耗时: %v\n", time.Since(start))
        // defer确保无论是否panic都会打印耗时
        
        return fn(arg) 
        // 关键点：原样执行并返回结果
    }
}
```

 参数部分`fn func(T) R`

- 表示$fn$是一个函数参数
- 它需要一个$T$类型的参数，并返回一个$R$类型的结果。而不是**函数+返回值**同时传入

返回的增强函数指的是这个$F(fn)$这个整体是增强函数，同时这个增强函数的类型仍然是$fn$，只是对他的内容进行丰富了

新函数就有这个增强函数为他添加的功能了，相当于给手机套上了手机壳，给米饭加上了配菜，给函数打上了补丁。

**为什么这个方案比反射方案性能更好，反射方案是什么？**

- 对比反射来说，使用泛型的方案类型安全，有编译检查，运行开销几乎为$0$，且高可读性。

```go
//使用反射实现
func ReflectInterceptor(fn interface{}, args ...interface{}) {
    v := reflect.ValueOf(fn)
    if v.Kind() != reflect.Func {
        panic("必须传入函数！")
    }

    // 构造参数
    params := make([]reflect.Value, len(args))
    for i, arg := range args {
        params[i] = reflect.ValueOf(arg)
    }

    // 调用函数
    v.Call(params)
}
```



**使用$interface\{\}$作为参数这样写就是反射方案吗，此时需要运行到这一步的时候$interface$来检测类型的时候才会发现。这样理解对吗？**

**对的**

- $interface\{\}$是**编译期类型擦除**的容器
- 运行时必须用$reflect$包**探测真实类型**
- 类型错误要到**运行时才会暴露**（$panic$风险）

## 拦截器与过滤器

```tex
🛂 拦截器(Interceptor)：
  → 像机场安检员，可以：
     ✔️ 拦截可疑行李（阻断流程）
     ✔️ 开箱检查（修改参数）
     ✔️ 贴安检标签（添加元数据）

🛡️ 过滤器(Filter)：
  → 像快递分拣机，专门：
     ✔️ 按尺寸筛选（类型检查）
     ✔️ 自动分流（路由控制）
     ✔️ 去除危险品（数据净化）
     
🔹 拦截器是"流程警察" 👮♀️
🔹 过滤器是"数据保姆" 🧹
🔹 拦截器管"能不能过"
🔹 过滤器管"干不干净"
```

**拦截器**

```go
func Interceptor(next HandlerFunc) HandlerFunc {
    return func(c *Context) {
        // 1. 前置处理（开箱检查）
        if c.Request.危险品 { 
            c.Abort() // 拦截！
        }
        
        // 2. 放行原始处理
        next(c)
        
        // 3. 后置处理（贴标签）
        c.Response.Header.Set("安全检查", "通过")
    }
}
```

## 产品逻辑

**产品逻辑思维四要素**

- **原子性：**像乐高基础颗粒 → 最小可用单元
     示例：用户系统的「密码验证」模块

- **流程性：**拼装说明书步骤 → 严谨的工作流
     示例：电商订单的「创建→支付→发货」链条

- **扩展性：**预留的接口凹槽 → 可插拔设计
     示例：支付系统支持多支付渠道的抽象接口

- **防御性：**积木的防误插设计 → 异常处理
     示例：文件上传时的格式校验和大小限制



## $HTTP$相关

### $HTTP$状态码

**$HTTP$状态码是服务器对客户端请求的响应。**

状态码分为五类：

- **$1xx$（信息性状态码）**：表示接收的请求正在处理。
- **$2xx$（成功状态码）**：表示请求正常处理完毕。
- **$3xx$（重定向状态码）**：需要后续操作才能完成这一请求。
- **$4xx$（客户端错误状态码）**：表示请求包含语法错误或无法完成。
- **$5xx$（服务器错误状态码）**：服务器在处理请求的过程中发生了错误。



**HTTP 三点注意事项：**

- $HTTP$ 是无连接：无连接的含义是限制每次连接只处理一个请求，服务器处理完客户的请求，并收到客户的应答后，即断开连接，采用这种方式可以节省传输时间。
- $HTTP$ 是媒体独立的：这意味着，只要客户端和服务器知道如何处理的数据内容，任何类型的数据都可以通过$HTTP$发送，客户端以及服务器指定使用适合的 $MIME-type$ 内容类型。
- $HTTP$ 是无状态：$HTTP$ 协议是无状态协议，无状态是指协议对于事务处理没有记忆能力，缺少状态意味着如果后续处理需要前面的信息，则它必须重传，这样可能导致每次连接传送的数据量增大，另一方面，在服务器不需要先前信息时它的应答就较快
